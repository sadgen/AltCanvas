# 外部 agent 改动审计与文库收简（2026-10-14）

审计基线为生产提交 `37de12a`。本地代码与生产已提交代码一致；外部 agent 在生产额外增加了三个未跟踪脚本：`apply-report-metadata.mjs`、`auto-enroll-library.mjs`、`auto-sync-research-library.mjs`。原件在上线备份保存，修复后的脚本纳入版本管理。

## 发现与修复

| 优先级 | 原行为与后果 | 本次修复 |
|---|---|---|
| P1 | 两个元数据脚本在没有主题匹配时自动绑定默认主题，与“不强塞、允许多主题”的规则冲突 | 不匹配保持未分类；仅接受当前账户已有主题，保留所有有效匹配 |
| P1 | `--dry-run` 在判断试运行前已经调用扫描器，扫描会写 source_files、任务和扫描状态 | 试运行只预览已登记的待处理条目，不扫描、不入库、不调用 AI |
| P1 | 按 `%reportId%` 模糊查询再取最新一条；通配符或同名文件可能把标题回填到错误文章 | 优先 documentId；其他标识必须唯一，缺失/歧义整批拒绝，通配符按普通文本处理 |
| P1 | 元数据写入没有人工来源保护，缺失字段也清空已有机构、年份、摘要 | 保留人工元数据，稀疏输入合并原字段；事务内再次检查文档版本和元数据是否改变 |
| P1 | 自动入库选择所有 document_id 为空的文件，包含用户主动从文库移除的源文件 | 排除已有被移除文档附件历史的源文件，避免每天重新导入；排除已入库的相同哈希，避免占据处理上限 |
| P1 | 入库循环在同一个外层事务里捕获每个文件异常，内层事务没有独立回滚边界 | 每个入库调用独立提交/回滚，单文件失败不留下半成品，后续文件可继续 |
| P1 | 自动识别通过 path.join 读取文件，绕过受控文件系统的链接/路径检查 | 使用 openFileInsideRoot；Linux PDF 子进程读取已打开的文件描述符，TXT/EPUB 走现有安全文本提取 |
| P2 | 管理员 LIMIT 1、目录不存在时 roots[0] 回退，可能处理错误账户或目录 | 多管理员必须显式配置 ALTCANVAS_AGENT_USER；根目录名称必须唯一且启用扫描 |
| P2 | AI 无效 JSON/漏文档时把原文件名保存为“完成”，以后不再识别；失败时 CLI 仍可退出 0 | 严格检查每篇元数据与分类结果，失败保留待处理状态；CLI 返回失败状态 |
| P2 | 脚本自行强制允许私网和 HTTP，PDF-only 提取，缺乏输入上限 | 复用现有 CPA 配置、不强制放宽；支持 PDF/TXT/EPUB；限定批量/文本/输出预算 |
| P2 | 原文库的“重命名”按钮传 rename-original，但处理器只实现 rename | 新菜单调用已实现的 rename 路径，补行为测试 |

## 左侧列表

- 默认每篇只显示标题、单行机构/年份或主题提示，异常文件状态仍显式可见；原始文件列表显示入库状态与大小。
- 文档编号、原始文件名、完整主题列表放到三点菜单信息区。
- 编辑标题来源、加入主题、重命名、移动、文库移除、回收站与恢复放到菜单，沿用原有版本冲突/确认流程。
- 文章点击直接阅读，保留勾选与批量导读；目录菜单支持选择目录中的文章。
- 文库的低频排序、全选、AI 分类、主题管理、回收站入口收进顶部菜单。
- 菜单使用页面级固定定位，避免被滚动面板裁切；支持 Escape、方向键、外部点击关闭和焦点返回。文件与文章元数据以纯文本显示。

## 验证与边界

完整测试链增加自动脚本及菜单行为测试，共 17 套；包括错误账户/目录、试运行、模糊匹配歧义、人工标题保留、无效 AI 结果可重试、独立回滚、人工移除不重导入、多主题白名单、菜单键盘/定位/操作绑定。

三个自动脚本的业务范围仍是扫描、入库、元数据与已有主题分类。它们没有自动阅读全文生成导读的入口，也没有证明 Hermes 自身的每日调度已配置；本次审计没有把这两项宣称为已实现。只有一个管理员时兼容现有无参数调用；建议 Hermes 明确设置 `ALTCANVAS_AGENT_USER=sadgen`，并优先用 documentId 回填元数据。

历史已写入的标题与分类需要结合原文独立核对。本次仅部署代码修复与 UI，不运行真实分类、不自动回溯重写已有文章。

UI 实机验收：Ctrl+F5，打开文库和原始文件列表，点三点菜单执行一个非破坏操作（例如编辑标题后取消），确认不会误打开文章；键盘 Escape 关闭。回复“完成/看日志”后检查项目日志。
