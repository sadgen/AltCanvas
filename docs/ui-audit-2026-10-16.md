# 网页 UI 审计与收简（v0.4.9）

本轮覆盖顶栏、文库、原始文件、阅读器宿主、导读、高级画板以及设置/分类/元数据弹窗。依据是当前源码、生产日志、实际事件处理和状态切换行为测试；不将其描述为已完成用户屏幕视觉验收。Reader 内部工具栏属于 vendor，未逐项改动。

## 首要缺陷

顶部 `select-topic-workspace` 原来只调用 `switchTopicWorkspace`，没有修改文库的 `libraryTopicFilter`。左侧另一个下拉却根据该变量筛选文章。于是顶部选 A，左侧可能仍显示全部或 B，看上去分类没有生效。此前 v0.4.8 验证了文库筛选 API 和左侧筛选，没有覆盖顶部入口，这一遗漏本轮补齐。

现只保留顶部一个分类下拉，选项包含“全部分类”。选分类直接刷新文库列表，并同步画板；从原始文件页选择分类会返回文库，全屏时恢复三栏，手机端切到文库页，确保筛选结果真正可见。点击“全部/未分类”会清空顶部分类值，不再出现两个入口各持一个状态。切换过程按请求顺序保护，较早的画板响应不会覆盖后续选择，画板加载失败也不把工作区和画板半更新成不同分类。

## 已处理的重复或误导控件

| 区域 | 原问题 | 本轮处理 |
| --- | --- | --- |
| 分类入口 | 顶部主题和左侧分类两个下拉，状态不同步 | 只保留顶部一个；显示“分类”，真实控制文库筛选 |
| 分类管理 | 顶部齿轮、左侧管理按钮、文库菜单重复入口 | 保留顶部齿轮；未选择具体分类时禁用，避免管理隐藏的旧画板分类 |
| 分类设置 | 打开、关闭、保存、删除和页签事件均绑定两遍 | 移除重复绑定；一次点击只执行一次处理 |
| 全屏 | 默认导读页顶栏仍显示“全屏画板” | 移到右栏三点菜单；导读显示“全屏导读”，画板显示“全屏画板”，全屏后可“恢复三栏” |
| 右栏标题区 | 常驻高级画板按钮和刷新图标占据空间 | 移入三点菜单；保留“阅读全文”为默认主操作 |
| 默认导读工具栏 | 同时出现阅读全文、重新分析、加入标注 | 重新生成放入三点菜单；加入标注保留在高级画板，导读“我的标注”直接读取实际标注 |
| 右栏计数 | 默认导读显示整个画板的节点数，容易误认成当前文章的标注数 | 默认导读隐藏该计数，高级画板仍显示 |
| 文库菜单 | 已有常驻 AI 按钮，菜单再提供同一 AI 操作 | 删除菜单中的重复项；保留全选、排序、刷新、回收站 |
| 元数据编辑 | 发布年份与发布日期两个输入可能互相矛盾 | 只保留发布日期，接受年/月/日不同精度；保存时派生兼容 year 字段，旧的只有年份数据仍可编辑 |
| 上传/重命名文案 | 实际支持 PDF/TXT/EPUB，却写“上传 PDF”“保持 .pdf 扩展名” | 改成“上传文件”“保留原扩展名” |
| 分类设置文案 | 标题仍提已经退役的 Collection 绑定 | 改为“分类设置”，保留分类规则、所属文章两页 |
| 元数据弹窗 | 多个字段没有高度限制，小屏可能无法到达保存按钮 | 限制为视口高度并允许弹窗内部滚动 |
| 文库数量 | 清空分类后可能保留上个分类的数量 | 全部/未分类/分类列表分别更新实际篇数 |

同时修正隐藏的快速导入入口使用已不存在的 `currentTopicWorkspaceId` 变量，改用当前工作区 ID；未新增导入、AI 或跨文章关系调用。

## 应保留的功能

| 区域 | 保留理由 |
| --- | --- |
| 文库 / 原始文件两种页签 | 前者是文章与分类，后者是磁盘目录、扫描、移动、重命名；两者处理对象不同 |
| AI 识别归类 / 阅读全文 | 前者提取前序元数据和归类，后者实际读取正文形成导读，不能混成一个按钮 |
| 全部 / 未分类 | 是文章范围筛选；未分类可与“属于哪个分类”明确区分 |
| 多选与生成所选导读 | 作用于指定文章集合，不等同当前文章的阅读全文 |
| 我的标注 / 导读 | 一个承载用户笔记与正式标注，一个承载文章解释，各自保留 |
| 分类的研究问题与纳入/排除规则 | 是 AI 分类的上下文，保留在设置中即可，无须放到首屏 |
| 易读名称 / 主标题 / 摘要 | 完整展示名与结构化字段用途不同，不能因字段多而直接删数据 |
| 高级画板的连线、布局、缩放、大纲 | 适合空间分析，在高级模式保留，不进入默认阅读工具栏 |
| AI 进度、取消、错误状态 | 用于判断真实进度和停止耗时任务，不应因精简而隐藏 |
| 原始文件状态、复制原文路径、回收站 | 状态避免误操作，路径用于现有 agent 协作，删除恢复能力需保留 |

## 后续建议与验收边界

- 原始文件页的递归扫描、新建目录和排序可进一步合并到文件页菜单；本轮保留，避免把后台入库控制做成难发现的操作。
- 顶栏账号、上传和分类在窄屏的实际拥挤程度，以及元数据弹窗滚动/全屏恢复，需要用户实机确认；没有仅根据源码宣称布局已经满意。
- Reader iframe 内部功能先保留。涉及选区、批注、搜索与 PDF 工具栏的精简，应结合真实阅读操作单独评估，不能把 vendor 按钮直接认作冗余。

新增行为测试直接执行顶部下拉事件，覆盖分类/全部/未分类互斥、原始文件页返回、连续切换竞态、画板失败保持文库筛选、分类设置单次事件、三点菜单操作及日期单一输入的兼容保存。

人工最短复验：Ctrl+F5 → 顶部选两个不同分类观察左侧篇数/文章 → 点未分类再选全部 → 右侧三点菜单检查高级画板/全屏/恢复三栏。回复“完成/看日志”后查看生产 `.debug/browser.log`；临时开发诊断 `library.category-filter` 仅记录结果数量，无分类名/文献名/正文，验收后移除。
