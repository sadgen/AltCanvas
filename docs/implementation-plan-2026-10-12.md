# 三模块完善计划与交付记录

## 产品规则

- 左：配置目录选取/网页上传 → 元数据识别 → 优先归入现有主题。一篇文献允许多个主题。仅当现有主题无法合理覆盖且模型给出具体理由时新增，保留用户已有分类，不强制塞进最高分主题。
- 中：PDF 保留现有 Reader；TXT/EPUB 用安全的文本章节阅读视图，支持选区标注、持久化及来源回跳。
- 右：围绕问题、推理、证据、结论与限制导读，紧凑卡片和详情互补；保留跨文章画板，不自动清空或覆盖人工内容。
- 局域网 CPA 地址、模型与密钥不变，不清空生产文库或主题。

## 实施阶段

1. **分类与识别**：多主题采纳；已有主题优先；新增主题需要必要性理由与实际使用；每篇提取正文，消除 25/50 不一致；上传自动识别；识别失败保留入库结果。
2. **完整与可信阅读**：文库与 Reader 全文提取统一上限，超限明确拒绝；只接受真实匹配引用，不把不相关句子当证据；展示引用待核验；控制生成预算、处理截断；升级缓存版本并提供强制重分析。
3. **导读与操作**：根据文体解释问题/推理/证据/结论/限制；减少凑数；结构连线与支持关系分开；恢复标注加入画板；整理用确定性布局，检查并发版本，保留人工内容。
4. **文件格式**：贯通 PDF/TXT/EPUB 的扫描、上传校验、MIME、文件操作与回收站；文本格式按章节/段落提供来源定位，安全提取 EPUB，禁止执行书内 HTML/脚本。
5. **维护和回归**：提取共享格式/AI 逻辑，移除确认无调用的占位代码；修复 Windows 日志启动及测试目录清理；更新当前架构说明和版本。
6. **交付**：本地测试与日志检查 → Git 提交/推送 → 5.237 同步前备份 SQLite 与代码版本 → Linux 全套测试 → 重启 altcanvas.service → 版本/健康/日志确认；失败则恢复旧代码，数据库不做破坏性操作。

## 验收标准

- 有现有主题时不因批次再次造一套分类；一篇文章的两个有效建议均采纳，低相关不强制归入；新增主题有必要性依据。
- 长于 40 页文章读取全文；超字符/请求体预算给明确错误，无静默截断。
- 杜撰引用显示待核验且不可转批注；真实引用可回跳。
- 新 prompt 缓存版本独立；手动重分析能绕过缓存。
- 上传后识别、目录识别行为一致，中文标题独立于原始文件名。
- TXT/EPUB 可打开、标注、刷新保留、加入右侧、生成全文图及回跳；PDF 路径无回归。
- 本地及 Linux 自动测试通过；真实生成效果/UI 验收按人机协作方式操作，由 Agent 看日志。

## 实施记录

已完成 v0.3.0 开发：

- 分类采纳全部 >=0.7 的有效主题建议，保持已有绑定；新增主题必须有必要性理由、合格文献，且该文献没有已匹配的现有主题。每批最多新增一个，取消全库硬顶四个主题。
